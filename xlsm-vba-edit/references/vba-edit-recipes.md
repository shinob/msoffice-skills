# VBA 編集レシピ集

AI との協働で使うプロンプトと編集パターンの一覧。
`{xlsmファイル名}` は実際のファイル名（例: `gantt57asrc.xlsm`）に置き換えて使用する。

---

## 修正分析プロンプト

バグ・クラッシュリスク・コード品質問題を洗い出し、`_analysis.md` に書き出す。

```
msoffice-skills を使って @{xlsmファイル名} を分析してください。

以下の観点で調査し、結果をファイルに書き出してください。

1. ファイル概要（シート構成・VBAモジュール構成・主要機能）
2. 改善すべき点の調査
   - バグ・クラッシュリスク（優先度 High）
   - 未完成機能・機能不全（優先度 Medium）
   - コード品質・保守性（優先度 Low）
3. 各改善項目について、修正箇所・問題内容・修正方針をコード例付きで示す
4. 修正作業手順（推奨順序・工数見積もり・検証チェックリスト）

報告ファイル名: {xlsmファイル名}_analysis.md
```

### 報告ファイルの構成

| セクション | 内容 |
|-----------|------|
| ファイル概要 | シート数・モジュール数・作成日・最終保存日など |
| シート構成 | データシートとチャートシートの一覧と役割 |
| VBAモジュール構成 | クラス・フォーム・標準モジュールの一覧と役割 |
| 主要機能 | アプリケーションとして提供している機能の概要 |
| 改善調査結果 | 優先度 H/M/L 別の問題一覧（コード例・修正方針付き） |
| 修正作業手順 | VBA 変更方法・推奨実施順序・工数見積もり |
| 検証チェックリスト | 修正後に確認すべきテスト項目 |

## 機能追加プロンプト

追加したい機能をヒアリングし、`_features.md` に書き出す。2段階に分けて入力する。

**Phase 1 — 現状把握**（先に既存機能を整理させる）:

```
msoffice-skills を使って @{xlsmファイル名} の現在の機能を把握してください。
シート構成・VBAモジュール・主要機能の一覧を簡潔にまとめてください。
```

**Phase 2 — ヒアリング＋提案**（Phase 1 完了後に入力）:

```
上記の現状を踏まえて、追加したい機能についてヒアリングしてください。
以下の点を確認しながら要件を整理し、結果をファイルに書き出してください。

ヒアリング項目:
1. どのような機能を追加したいか（目的・使いたい場面）
2. 操作方法のイメージ（メニューから？ボタン？自動で？）
3. 優先度・いつまでに必要か

ヒアリング完了後、以下を報告ファイルにまとめてください:
- 各要望の実現可能性と実装方針（コード例付き）
- 工数と影響範囲の見積もり
- 推奨実施順序

報告ファイル名: {xlsmファイル名}_features.md
```

### 報告ファイルの構成

| セクション | 内容 |
|-----------|------|
| 現状の機能概要 | 既存機能の一覧（ヒアリングの前提として整理） |
| ヒアリング結果 | ユーザーから聞き出した要望の一覧 |
| 機能追加提案 | 各要望の実現方法・コード例・影響範囲 |
| 工数見積もり | 各機能の実装コスト（小/中/大） |
| 推奨実施順序 | 依存関係・優先度を考慮した実施順 |
| 検証チェックリスト | 実装後に確認すべき動作確認項目 |

## 修正依頼プロンプト

`_analysis.md` の修正項目を `_VBA/` ファイルに適用する。

```
@{xlsmファイル名}_analysis.md の修正項目を確認し、
@{xlsmファイル名}_VBA/ 内の対象ファイルに修正を適用してください。

完了後、以下をまとめてください:
1. 修正したファイルの一覧
2. 各ファイルの変更内容のサマリー
3. VBE への貼り付け手順（どのフォルダのどのファイルをどのモジュールに貼るか）
```

一部だけ適用したい場合はプロンプト末尾に指定する:

```
（上記に追加）
今回は H-1 と H-2 のみ適用してください。
```

---

## 確認依頼プロンプト

VBE への貼り付けと保存が完了した後、反映を確認させる。

```
export_vba.py で {xlsmファイル名} を再書き出しし、
修正したファイルと内容が一致しているか diff で確認して結果を報告してください。

確認コマンド例:
python3 path/to/export_vba.py {xlsmファイル名}
diff {xlsmファイル名}_VBA/{サブフォルダ}/{モジュール名} {新しい書き出し先}/{モジュール名}
```

---

## 統合プロンプト（修正 + 機能追加を同時に適用）

`_analysis.md` と `_features.md` の両方を同一セッションで適用する場合:

```
@{xlsmファイル名}_analysis.md の未対応項目 および
@{xlsmファイル名}_features.md の実装提案を確認し、
@{xlsmファイル名}_VBA/ 内の対象ファイルに修正を適用してください。

適用順:
1. _analysis.md の H（High）項目をすべて適用
2. _features.md の優先度 High の機能を適用
3. 依存関係がある場合は順序を守ること

完了後、修正ファイル一覧と VBE 貼り付け手順をまとめてください。
```

---

## 推奨実行順序

```
修正分析（_analysis.md 作成）
    ↓
機能追加検討（_features.md 作成）   ← 修正分析の後に実施
    ↓
修正依頼プロンプト（または統合プロンプト）
    ↓
確認依頼プロンプト
```

修正分析を先に行う理由: 既存バグが残った状態で機能追加を行うと、後で原因の切り分けが困難になるため。
