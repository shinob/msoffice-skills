# DOCX Text Structure Reference

## DOCX as a ZIP Package

A `.docx` file is a ZIP archive. Unpack it to inspect raw XML:

```bash
python3 skills/docx-text-ops/scripts/unpack.py document.docx unpacked/
```

Key files after unpacking:

```
unpacked/
├── word/
│   ├── document.xml          # main body text — primary edit target
│   ├── styles.xml            # paragraph and character styles (do not edit for text changes)
│   ├── settings.xml          # document settings
│   ├── numbering.xml         # list and numbering definitions (do not edit for text changes)
│   ├── fontTable.xml
│   ├── header1.xml           # section header(s)
│   ├── footer1.xml           # section footer(s)
│   ├── footnotes.xml         # footnote text
│   ├── endnotes.xml          # endnote text
│   ├── comments.xml          # reviewer comments
│   ├── theme/
│   │   └── theme1.xml
│   ├── media/                # embedded images
│   └── _rels/
│       └── document.xml.rels # relationships (headers, footers, images, footnotes, etc.)
├── [Content_Types].xml
└── _rels/
    └── .rels
```

## Where Text Lives

### Body Paragraphs

File: `word/document.xml`

XML path:

```
w:document
  w:body
    w:p                      ← paragraph
      w:pPr                  ← paragraph properties (style, alignment, indent)
        w:pStyle w:val="..."
      w:r                    ← run (inline formatting unit)
        w:rPr                ← run properties (bold, italic, font, size)
          w:b/
          w:i/
        w:t                  ← actual text content
```

Example:

```xml
<w:p>
  <w:pPr>
    <w:pStyle w:val="Heading1"/>
  </w:pPr>
  <w:r>
    <w:rPr><w:b/></w:rPr>
    <w:t>Section Title</w:t>
  </w:r>
</w:p>
<w:p>
  <w:r>
    <w:t xml:space="preserve">Body text with a </w:t>
  </w:r>
  <w:r>
    <w:rPr><w:i/></w:rPr>
    <w:t>italic phrase</w:t>
  </w:r>
  <w:r>
    <w:t xml:space="preserve"> here.</w:t>
  </w:r>
</w:p>
```

### Table Cell Text

Tables appear in `word/document.xml` inline with body paragraphs:

```xml
<w:tbl>
  <w:tr>                       ← table row
    <w:tc>                     ← table cell
      <w:p>
        <w:r><w:t>Cell text</w:t></w:r>
      </w:p>
    </w:tc>
  </w:tr>
</w:tbl>
```

Cells contain full paragraph structures. Edit the `<w:t>` content directly.

### Headers and Footers

Files: `word/header1.xml`, `word/footer1.xml`, etc.

Each section can have up to three header/footer variants:
- Default (odd pages): `word/header1.xml`
- First page: `word/header2.xml` (if `<w:titlePg/>` is set in section properties)
- Even pages: `word/header3.xml` (if `<w:evenAndOddHeaders/>` is set)

Same `w:p / w:r / w:t` structure as body paragraphs.

### Footnotes and Endnotes

File: `word/footnotes.xml`, `word/endnotes.xml`

```xml
<w:footnotes>
  <!-- id="-1" and id="0" are separator/continuation marks — do not edit -->
  <w:footnote w:id="-1" w:type="separator">...</w:footnote>
  <w:footnote w:id="0"  w:type="continuationSeparator">...</w:footnote>

  <!-- id="1" onward are actual footnotes -->
  <w:footnote w:id="1">
    <w:p>
      <w:r>
        <w:rPr><w:vertAlign w:val="superscript"/></w:rPr>
        <w:t>1</w:t>           ← footnote reference number (generated by Word)
      </w:r>
      <w:r>
        <w:t xml:space="preserve"> Footnote body text.</w:t>
      </w:r>
    </w:p>
  </w:footnote>
</w:footnotes>
```

Edit only the body text runs, not the reference number run.

### Comments

File: `word/comments.xml`

```xml
<w:comments>
  <w:comment w:id="1" w:author="Jane" w:date="2026-01-01T00:00:00Z">
    <w:p>
      <w:r><w:t>This paragraph needs revision.</w:t></w:r>
    </w:p>
  </w:comment>
</w:comments>
```

### Text Boxes

Text boxes are anchored shapes embedded in `word/document.xml`:

```xml
<w:p>
  <w:r>
    <w:drawing>
      <wp:anchor ...>
        <a:graphic>
          <a:graphicData uri="http://schemas.microsoft.com/office/word/2010/wordprocessingShape">
            <wps:wsp>
              <wps:txbx>
                <w:txbxContent>
                  <w:p>
                    <w:r><w:t>Text box content</w:t></w:r>
                  </w:p>
                </w:txbxContent>
              </wps:txbx>
            </wps:wsp>
          </a:graphicData>
        </a:graphic>
      </wp:anchor>
    </w:drawing>
  </w:r>
</w:p>
```

Search for `<w:txbxContent>` to locate all text boxes:

```bash
grep -n "txbxContent" unpacked/word/document.xml
```

## The Split-Run Problem

A phrase that appears visually as one string may be split across multiple `<w:r>` runs. This is common when:

- Text was partially formatted (bold, italic, font size change mid-phrase)
- Text was edited incrementally in Word
- Auto-correct or spell-check inserted runs
- Tracked changes created adjacent runs with different revision metadata

Example — "Hello World" split across two runs:

```xml
<w:p>
  <w:r>
    <w:rPr><w:lang w:val="ja-JP"/></w:rPr>
    <w:t xml:space="preserve">Hello </w:t>
  </w:r>
  <w:r>
    <w:rPr><w:b/><w:lang w:val="ja-JP"/></w:rPr>
    <w:t>World</w:t>
  </w:r>
</w:p>
```

A simple regex search for `Hello World` finds nothing. A naive `<w:t>` replacement breaks the text.

**How to handle split runs:**

- Inspect the full paragraph `<w:p>` block before replacing.
- If formatting should be uniform, collapse the runs into one `<w:r>`.
- If formatting differences must be preserved, replace each run's `<w:t>` separately.
- See [text-edit-recipes.md](text-edit-recipes.md) for patterns.

## Tracked Changes

When Word's track changes feature is active, edits are stored as revision marks:

```xml
<w:p>
  <w:r><w:t>Original text </w:t></w:r>
  <w:ins w:id="5" w:author="Alice" w:date="2026-01-01T00:00:00Z">
    <w:r><w:t>inserted text </w:t></w:r>
  </w:ins>
  <w:del w:id="6" w:author="Alice" w:date="2026-01-01T00:00:00Z">
    <w:r><w:delText>deleted text</w:delText></w:r>
  </w:del>
</w:p>
```

**Never edit `<w:ins>` or `<w:del>` runs directly.** This produces corrupt revision state that Word may refuse to open or display incorrectly.

If `extract.py` reports a WARNING about tracked changes, ask the user to open the file in Word and accept or reject all changes (`Review → Accept All` or `Reject All`) before proceeding.

## Namespace Handling

DOCX XML uses multiple namespaces. Key prefixes:

| Prefix | Namespace URI | Used for |
|--------|---------------|----------|
| `w:` | `.../wordprocessingml/2006/main` | Document body, paragraphs, runs, tables |
| `r:` | `.../officeDocument/2006/relationships` | Relationship IDs |
| `a:` | `.../drawingml/2006/main` | Drawing elements, text in shapes |
| `wp:` | `.../drawingml/2006/wordprocessingDrawing` | Drawing anchors |
| `wps:` | `.../office/word/2010/wordprocessingShape` | Word text box shapes |

When parsing XML programmatically, always use namespace-aware tools:

```python
from docx.oxml.ns import qn
# qn("w:t") → "{http://schemas.openxmlformats.org/wordprocessingml/2006/main}t"
```

Never use regex-only replacement on XML — it silently corrupts namespace declarations.

## Relationship Files

`word/_rels/document.xml.rels` links the body to headers, footers, images, footnotes, etc.:

```xml
<Relationships>
  <Relationship Id="rId1" Type=".../header"    Target="header1.xml"/>
  <Relationship Id="rId2" Type=".../footer"    Target="footer1.xml"/>
  <Relationship Id="rId3" Type=".../footnotes" Target="footnotes.xml"/>
  <Relationship Id="rId4" Type=".../image"     Target="media/image1.png"/>
</Relationships>
```

**Never modify `.rels` files for text-only changes.**

## Whitespace

Use `xml:space="preserve"` on `<w:t>` elements with leading or trailing spaces:

```xml
<w:t xml:space="preserve"> leading space</w:t>
```

Without this attribute, XML parsers strip edge whitespace, breaking text silently. When adding new runs with surrounding spaces, always include this attribute.
